# 決策紀錄撰寫規則

檔案：`docs/決策紀錄.md`（repo 根目錄 `C:\Users\oright\Desktop\沙龍\DM`）

## 何時記

- 要記：使用者選擇了提供的選項；指定具體做法；否決或更正 Claude 的提案；指示暫緩、不處理或保留某事。
- 不記：使用者沒有參與決定的實作細節。
- 同一則訊息裡有多個決定時，分成多條。

## 編號

- 格式 `D-NN`，接續檔案中目前最大的編號。
- 編號不重用、不重排。

## 寫在哪裡

- 依分節標題 `## YYYY-MM 主題` 分組，新的分節放在最上面。
- 同一分節內，新條目放在最上面。
- 當月已有主題相近的分節時，加進該分節；否則新增分節。

## 條目格式

- 標題：`### D-NN｜決定內容一句話（M/D）`
- 欄位依情況使用，順序固定：
  - **選項**：有提供選項時，列出全部選項與代號。
  - **決定**：選了什麼、具體怎麼做。
  - **理由**：見下方「理由規則」。
  - **附帶決定**：同一件事裡的次要決定。
  - **代價**：有明顯代價時才寫。
- 決定內容含判斷分支或步驟順序時，附 Mermaid flowchart，並以 Mermaid 實際解析並繪製一次，確認能畫出。
- 不寫人名與內部對話內容（網站公開）。

## 理由規則

- 只寫使用者說過、或紀錄中查得到的理由。
- 查不到理由時寫「理由待補」。
- 禁止推測，禁止寫「推測：」。
- 使用者更正 Claude 的提案時，寫「使用者更正（原提案為 X）」。
- 使用者只說了選擇、沒說原因時，寫「使用者指定」或「使用者選擇」。

## 推翻舊決定

- 新增一條新決定，在「決定」欄註明「取代 D-NN」。
- 舊條目不刪除，在其「決定」欄後加「（已由 D-NN 取代）」。

## 步驟

1. 讀取 `docs/決策紀錄.md`，取得目前最大編號，找到對應分節。
2. 依上述格式寫入條目。
3. 與該步其他檔案一起 commit。
