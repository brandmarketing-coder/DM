# 專案地圖維護規則

檔案：`docs/專案地圖.md`（repo 根目錄 `C:\Users\oright\Desktop\沙龍\DM`）

## 何時改

依該步的改動，找出要同步的段落：

| 改動類型 | 要檢查的段落 |
|---|---|
| 新增、刪除、搬移、改名檔案或資料夾 | 「資料夾與檔案」表格；「架構圖」圖 1 |
| 改變資料的來源或流向（誰產生誰、誰讀取誰） | 「資料怎麼流進編輯器」流程圖；「架構圖」圖 1 |
| `Coding/index.html` 內函式分組、呼叫關係改變 | 「架構圖」圖 2 |
| 新增、移除或更換外部工具、字型 | 「外部依賴」表格；「架構圖」圖 1 |

改動不涉及以上任何一類時，不修改專案地圖。

## 內容規則

- 只更新受影響的段落，不改動其他段落的內容與用字。
- 不新增使用者未同意的段落或說明區塊。
- 「資料夾與檔案」表格欄位固定為：位置｜是什麼｜什麼時候會動到它。每列寫一個檔案或一組同性質的檔案。
- 檔案或資料夾刪除時，刪掉對應的表格列、圖中的方框與箭頭。
- 用白話描述用途，不寫程式細節；第一次出現的技術術語依 `docs-glossary` 規則處理。
- 不寫人名與內部對話內容（網站公開）。

## 圖的規則

- 所有圖一律用 Mermaid 區塊。
- 圖 1 每個方框代表一份檔案或資料夾，框內列出它負責的內容；箭頭標「讀取／產生／載入」等關係。
- 圖 2 每個方框代表 `Coding/index.html` 內一組負責同一件事的函式，箭頭表示呼叫關係；方框內列出的函式名稱必須確實存在於程式中。
- 修改任何一張圖後，以 Mermaid 實際解析並繪製一次，確認能畫出。

## 步驟

1. 列出該步新增、刪除、搬移、改名的檔案，以及關係或函式分組的變化。
2. 依「何時改」表找出受影響的段落。
3. 修改段落；圖有改動時執行繪製檢查。
4. 與該步其他檔案一起 commit。
